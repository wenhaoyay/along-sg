# V0.7 private beta operations

## Deployment shape

V0.7 uses one Docker web service. A multi-stage build exports the Next.js UI as static files, and FastAPI serves both those files and `/api/*` from one origin. One Python process owns the existing POI SQLite database and a separate analytics SQLite database under `/data`. This is intentionally suitable only for a 30–50 person private beta: a persistent disk permits one service instance, so horizontal scaling is out of scope.

`render.yaml` selects Render’s Singapore region, a Starter web service and the smallest 1 GB persistent disk. `ONEMAP_EMAIL` and `ONEMAP_PASSWORD` are secret prompts (`sync: false`); `BETA_ADMIN_TOKEN` is generated by the platform. The frontend bundle has no secret configuration and uses same-origin API requests.

On every container start, `prepare_beta_data.py` creates the data schema and imports the bundled attributed Singapore OSM capture only when the persistent POI database is empty. Analytics schema initialization also removes expired events.

## Analytics event schema

`analytics_events` contains only:

- `event_id`, `anonymous_user_id`, `session_id`, optional `search_id` (random UUIDs);
- server-generated `occurred_at`;
- an allowlisted event type;
- optional recommendation key/rank;
- optional allowlisted feedback value/reason;
- optional deterministic/LLM parse method and optimisation latency.

The request model forbids additional properties. It therefore cannot accept coordinates, place queries, errand text, arbitrary metadata, IP addresses or user-agent fingerprints.

Event types are: `app_opened`, `search_started`, `intent_parsed`, `clarification_requested`, `interpretation_corrected`, `optimization_completed`, `optimization_failed`, `no_convenient_option`, `recommendation_viewed`, `recommendation_selected`, `navigation_clicked`, `alternative_selected`, `feedback_submitted`, `trip_feedback_submitted`, and `return_usage`.

## Metric definitions

The authenticated `GET /api/admin/analytics` report and `scripts/analytics_report.py` provide:

- distinct anonymous UUIDs, distinct searches and searches per user;
- completed distinct searches divided by started searches;
- searches corrected or ending with no convenient option divided by started searches;
- distinct completed searches selecting rank 1 or clicking navigation;
- selected searches that chose an alternative;
- positive/negative recommendation feedback and grouped negative reasons;
- median and nearest-rank P95 completed-optimisation latency;
- distinct users active today and during the inclusive last seven days;
- users appearing on at least two UTC dates, return rate and explicit browser return events.

Rates need an adequate observation window and denominator. A zero means no qualifying observation, not proven product success or failure.

## Retention, backups and recovery

The default event retention is 90 days. Expired rows are deleted during app startup. Keep the deployment to one process/instance and monitor `/data` disk usage.

Render disk snapshots are encrypted and automatic, but restoring a raw snapshot of an active custom database can be unsafe. For operational backups, open the service shell and run:

```sh
python backend/scripts/backup_beta_data.py --data-dir /data --output-dir /tmp/beta-backup
```

The script uses SQLite’s online backup API for consistent copies. Transfer them to restricted encrypted storage, test restoration on a separate copy, and remove each backup before its contained analytics events exceed the configured retention period. Never download `.env` or access tokens with a backup.

## Publish checklist

1. Put the repository in a private GitHub or GitLab repository; confirm `.env` is absent.
2. In Render, create a Blueprint from the repository’s root `render.yaml`.
3. Enter `ONEMAP_EMAIL` and `ONEMAP_PASSWORD` when Render prompts. Do not add either as a build argument or `NEXT_PUBLIC_*` variable.
4. Deploy and wait for `/health` to return `{"status":"ok","onemap_mock":false}`.
5. Open the generated HTTPS URL on a phone, allow foreground location only if desired, and run one known Singapore journey.
6. Retrieve the generated `BETA_ADMIN_TOKEN` from the service environment and keep it in the beta operator’s password manager. Query the aggregate report with an `Authorization: Bearer` header; never put this token in the browser app.
7. Confirm the disk is attached at `/data`, review daily disk/backups, and run the credential scan before each release.

The deployment URL itself cannot be created from this local workspace without the operator choosing a Git host and authorising a Render account; those are the only required manual publishing actions.
